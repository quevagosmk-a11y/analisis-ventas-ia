CONSIDERACIONES GENERALES DEL MANUAL 
TÉCNICO 
El manual técnico es un documento dirigido a personal especializado, encargado 
de la instalación, configuración, mantenimiento, despliegue, soporte y 
evolución del sistema . A diferencia del manual de usuario, este documento sí 
describe aspectos internos, arquitectónicos y tecnológicos del sistema. 
Actualización importante: 
Hoy no es obligatorio entregar el manual en HTML; sin embargo, es válido indicar 
que el manual puede presentarse en formato digital (Word o PDF)  y, 
opcionalmente, en repositorios técnicos (Markdown, Wiki, Git). El manual de 
usuario en video es un complemento, no un reemplazo.

3. ASPECTOS TÉCNICOS DEL DESARROLLO DEL 
SISTEMA 
3.1 Arquitectura del sistema 
Descripción general de las capas: 
a. Capa de presentación 
La capa de presentación corresponde al componente del sistema encargado de la 
interacción con el usuario final. Su función principal es permitir la visualización de 
la información y la captura de datos de manera clara, intuitiva y controlada. 
En este apartado se debe describir: 

===== PAGE 5 =====
• Tecnologías utilizadas (por ejemplo, HTML, CSS, JavaScript, frameworks 
web o interfaces gráficas). 
• Tipo de interfaz (web, escritorio, móvil). 
• Principios de usabilidad aplicados. 
• Forma en que el usuario navega e interactúa con el sistema. 
i. Relación de directorios 
Aquí se  debe explicar la estructura de carpetas  que componen la capa de 
presentación, indicando la función de cada directorio relevante. 
Ejemplo: 
• /views: contiene las vistas o pantallas del sistema. 
• /assets: almacena recursos como imágenes, hojas de estilo y scripts. 
• /components: agrupa elementos reutilizables de la interfaz. 
El objetivo es que un desarrollador pueda identificar rápidamente dónde se 
encuentra cada elemento visual del sistema. 
ii. Mapa de navegación o estructura del sistema 
Este subapartado describe la organización lógica de las pantallas y la forma en 
que el usuario se desplaza entre ellas. 
Se debe indicar: 
• Pantalla inicial 
• Menús principales 
• Submenús 
• Flujo general de navegación 
Ejemplo: 
Desde la pantalla principal el usuario puede acceder al mó dulo de gestión de 
clientes, donde puede registrar, consultar o modificar información. 
iii. Archivos de configuración 
En este apartado se describen los archivos que controlan parámetros generales 
del sistema, sin entrar en código fuente detallado. 
Debe indicarse: 
• Nombre del archivo 
• Propósito 

===== PAGE 6 =====
• Tipo de configuraciones que contiene (rutas, conexiones, variables de 
entorno) 
Ejemplo: 
Un archivo de configuración define la URL del servidor, el idioma del sistema y el 
modo de ejecución (desarrollo o producción). 
c. Capa de base de datos 
La capa de base de datos es responsable del almacenamiento, organización y 
recuperación de la información del sistema de manera estructurada y segura. 
En este apartado se debe describir: 
• Tipo de base de datos utilizada (relacional, no relacional). 
• Motor de base de datos. 
• Estructura general de la información. 
• Políticas básicas de integridad y consistencia. 
i. Diagrama entidad–relación 
Se debe presentar el diagrama y explicar brevemente: 
• Entidades principales 
• Relaciones entre ellas 
• Llaves primarias y foráneas 
Ejemplo: 
La entidad Cliente se relaciona con la entidad Pedido, donde un cliente puede 
realizar varios pedidos. 
ii. Diccionario de datos 
Aquí se documentan las tablas y campos principales, indicando: 
• Nombre del campo 
• Tipo de dato 
• Descripción 
• Restricciones relevantes 
El objetivo es que cualquier desarrollador pueda comprender la estructura de la 
base de datos sin necesidad de acceder directamente al gestor.
